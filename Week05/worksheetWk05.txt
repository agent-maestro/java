1. In one sentence, what is an ArrayList in Java and where does it live?

A resizable list that keeps its elements in order, and it lives in the
java.util package.

2. Fill in the import and declaration for an empty ArrayList<String> names.

import java.util.ArrayList;

ArrayList<String> names = new ArrayList<>();   // Empty list, size() is 0.

<String> means it only holds Strings. the <> on the right just copies the
type from the left side.

3. True/False: ArrayList can grow and shrink automatically at runtime.

True

add() makes it bigger and remove() makes it smaller, you never set a
length.

4. Which is valid for ArrayList<Integer> — add(42), add(0, 42), or both?

Both.

ArrayList<Integer> nums = new ArrayList<>();
nums.add(42);        // Add to the end: [42]
nums.add(0, 42);     // Insert at index 0 and push the rest right: [42, 42]

20. Why prefer enhanced for-each over repeated get(i) in large lists?

It is shorter and there's no index to get wrong, and it works the same
on any collection. (get(i) is already fast on an ArrayList, the real
speed difference is on a LinkedList where get(i) has to walk from the
start every time.)

29. Fix ArrayList<int> list = new ArrayList<>();.

ArrayList<Integer> list = new ArrayList<>();

generics only take object types, so you use the Integer wrapper instead
of int. list.add(42) still works, Java boxes the 42 into an Integer for
you.

30. Why does names.get(2) throw for [A, B], and how can you prevent it?

    ArrayList<String> names = new ArrayList<>(List.of("A", "B"));
    System.out.println(names.get(2));

Two elements means the only indexes are 0 and 1, so get(2) throws an
IndexOutOfBoundsException. Check the index against size() first.

int i = 2;
if (i >= 0 && i < names.size()) {
    System.out.println(names.get(i));
} else {
    System.out.println("No element at index " + i);
}
Output: No element at index 2

31. Difference between these removes?

    nums.remove(1);
    nums.remove(Integer.valueOf(1));

nums.remove(1) removes whatever is at INDEX 1.
nums.remove(Integer.valueOf(1)) removes the first element whose VALUE
is 1.

ArrayList<Integer> a = new ArrayList<>(List.of(1, 2, 3));
a.remove(1);                     // [1, 3]

ArrayList<Integer> b = new ArrayList<>(List.of(1, 2, 3));
b.remove(Integer.valueOf(1));    // [2, 3]

32. Rewrite to program to the interface.

    ArrayList<String> logs = new ArrayList<>();

List<String> logs = new ArrayList<>();   // Declare as List, create as ArrayList.

needs import java.util.List;

that way if you ever switch to a LinkedList only the right side changes,
everything else that uses logs stays the same.

33. Why check isEmpty() or size() > 0 before get(0)?

get(0) on an empty list throws IndexOutOfBoundsException. Checking first
lets you handle the empty case instead of crashing.

if (!names.isEmpty()) {
    System.out.println(names.get(0));
} else {
    System.out.println("List is empty");
}

34. Which loop is safest for removing items while iterating?

An Iterator loop with it.remove().

removing straight from the list inside a for-each throws
ConcurrentModificationException because the loop's iterator notices the
list changed under it.

Iterator<String> it = names.iterator();
while (it.hasNext()) {
    String name = it.next();
    if (name.equals("Bob")) {
        it.remove();            // Remove through the iterator, not the list.
    }
}

or just names.removeIf(n -> n.equals("Bob")); for a simple condition.

36. Write static int max(ArrayList<Integer> a), assume non-empty.

static int max(ArrayList<Integer> a) {
    int largest = a.get(0);          // Start with the first element.
    for (int n : a) {
        if (n > largest) {           // Found something bigger?
            largest = n;             // Remember it.
        }
    }
    return largest;
}

SECTION 13 — BONUS: ITERATOR REMOVAL SAFETY
======================================================================

41. Fix the bug caused by removing from a list inside for-each.

    ArrayList<String> list = new ArrayList<>(List.of("keep", "drop", "keep"));
    for (String s : list) {
        if (s.equals("drop")) list.remove(s); // Unsafe during iteration
    }

the for-each is using an iterator behind the scenes, and list.remove()
changes the list without telling that iterator. it either throws
ConcurrentModificationException or quietly skips an element, so it is a
bug either way.

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("drop")) {
        it.remove();           // The iterator does the removing.
    }
}
System.out.println(list);
Output: [keep, keep]

shorter version: list.removeIf(s -> s.equals("drop"));

SECTION 14 — CHALLENGE: INVENTORY SYSTEM
======================================================================

42. Define Product(name, price), create an inventory, add four products,
    print average price, remove products with price < 10, sort ascending,
    and print remaining products.

import java.util.ArrayList;
import java.util.Comparator;

class Product {
    String name;
    double price;

    Product(String name, double price) {
        this.name = name;
        this.price = price;
    }
}

public class Main {
    public static void main(String[] args) {
        ArrayList<Product> inventory = new ArrayList<>();
        inventory.add(new Product("Mouse Pad", 5.00));
        inventory.add(new Product("Keyboard", 35.00));
        inventory.add(new Product("USB Cable", 8.00));
        inventory.add(new Product("Headset", 60.00));

        // Average of all four, before anything gets removed.
        double sum = 0;
        for (Product p : inventory) {
            sum += p.price;
        }
        double average = sum / inventory.size();
        System.out.printf("Average price: $%.2f%n", average);

        // Drop anything under $10.
        inventory.removeIf(p -> p.price < 10);

        // Cheapest first.
        inventory.sort(Comparator.comparingDouble(p -> p.price));

        for (Product p : inventory) {
            System.out.printf("%s: $%.2f%n", p.name, p.price);
        }
    }
}
Output:
Average price: $27.00
Keyboard: $35.00
Headset: $60.00

5 + 35 + 8 + 60 = 108, and 108 / 4 = 27. Mouse Pad and USB Cable get
removed, then 35 and 60 are already in order.

43. When would you choose an array over an ArrayList? (1–2 lines)

When I know the size up front and it won't change, like 12 monthly
totals or a 3x3 board, especially with primitives since int[] doesn't
need wrapper objects.

44. What's one bug ArrayList's API helps you avoid? (1–2 lines)

Running out of room. With an array you have to make a bigger one and
copy everything over yourself when it fills up, ArrayList just grows
when you call add().

45. Name one Collections utility (other than sort) to try next and why.

Collections.shuffle(list) randomly mixes up the order, good for
shuffling a playlist or a deck of cards.

Collections.shuffle(playlist);   // Random order every run.
