26) Briefly explain "variable shadowing."

Shadowing occurs when a declaration with a name hides another
accessible declaration with the same name in a nested scope.
Example: a setName(String name) parameter hides the object's name field;
this.name accesses the field explicitly.

SECTION 3 — WEEK 4: THE IMPORTANCE OF OOP (25 QUESTIONS)
======================================================================

1) In one sentence: What is OOP?

A way of organizing a program around objects that bundle data together
with the methods that work on that data.

2) Match term -> definition:

ENCAPSULATION -> keep the data and the methods that use it together and
                 control who can touch the data.
INHERITANCE   -> build a new class from an existing one so it reuses its
                 fields and methods.
POLYMORPHISM  -> one method name can do different things depending on
                 which object is actually there.
ABSTRACTION   -> show what something does and hide how it does it.

3) What benefit does encapsulation provide for security/maintenance?

Outside code can't change the data directly, so bad values get blocked
in a setter and the inside of the class can be rewritten without
breaking the code that uses it.

4) Identify the pillar illustrated:
class Animal {
    void sound(){ System.out.println("Some"); }
}
class Dog extends Animal {
    @Override
    void sound(){ System.out.println("Bark"); }
}

Inheritance. Dog extends Animal and overrides sound() with its own
version.

5) What will this print and which pillar?
   Animal a = new Dog();
   a.sound();

Bark. Polymorphism.

the reference is an Animal but the actual object is a Dog, so at
runtime Java runs Dog's sound() instead of Animal's.

6) Fill in: OOP models real systems using ______ and ______.

classes and objects

7) Give one reason large systems benefit from OOP.

The code gets split into classes that each own one piece of the system,
so you can change or test one piece without reading through everything
else.

8) True/False: Static methods are the core of OOP.

False

objects and their state are the core. a static method doesn't belong
to any object.

9) Why is composition often preferred over deep inheritance? (1 line)

A class just holds the parts it needs (has-a) and can swap them out,
instead of being stuck in a tall chain of parent classes where one
change up top breaks everything below.

10) What is a "God class," and why avoid it?

One giant class that tries to do everything. It is hard to read, hard
to test, and every change risks breaking something unrelated.

11) Choose the best practice:
    a) Many responsibilities per class
    b) Single, focused responsibility

b) Single, focused responsibility

12) Match pillar -> one-sentence example in banking.

ENCAPSULATION -> Account keeps balance private and only changes it
                 through deposit() and withdraw().
INHERITANCE   -> SavingsAccount extends Account and adds an interest
                 rate.
POLYMORPHISM  -> Account a = new SavingsAccount(); a.monthEnd(); runs
                 the SavingsAccount version of monthEnd().
ABSTRACTION   -> A Payment interface has pay() and the checkout code
                 doesn't care if a card or a bank transfer is
                 underneath.

13) Briefly define the "S" in SOLID and give a tiny example name.

Single Responsibility Principle: a class should do one job and have one
reason to change. Example: InvoicePrinter only prints invoices, it
doesn't calculate them.

14) What is abstraction aiming to hide?

The implementation details. You see what a method does, not how it
does it.

15) Which approach promotes reuse more naturally in OOP: classes or
    global helpers? Why?

Classes. A class packages the data with the methods that work on it, so
you reuse the whole thing by making a new object or extending it,
instead of copying loose helper functions around and hoping they still
fit.

17) Fill in: Polymorphism allows the same interface to have ______
    implementations.

different

18) Name one common OOP design pattern and its purpose (1 line).

Singleton: makes sure there is only ever one instance of a class (like
one database connection) and hands everyone that same one.

19) Why does OOP help teams collaborate?

Everyone can work on their own class as long as the team agrees on the
method names up front, so people aren't editing the same file and
stepping on each other.

20) True/False: OOP guarantees simplicity for tiny scripts.

False

a 10 line script doesn't need classes, it would just be extra typing.

21) Which is more OOP: returning a Receipt object or printing text
    inside a calculator method? Why?

Returning a Receipt object. The calculator just calculates, and the
Receipt holds the result so it can be printed, saved, or tested
separately. Printing inside the method mixes two jobs into one.

22) Briefly contrast OOP vs procedural for maintenance.

Procedural code is a list of functions all working on shared data, so
changing the data can break functions all over the program. OOP keeps
the data and its functions inside one class, so a change stays in one
spot.

23) What is the danger of exposing fields as public in large systems?

Any code anywhere can set them to anything, like a negative balance,
and when something breaks you can't tell where the bad value came from.

24) Give a real-world domain and list 3 classes you'd model.

Airline: Flight, Passenger, Booking

25) Short answer: How does OOP reduce bugs over time?

Private fields stop bad data from getting in, each class is small
enough to test on its own, and a change inside one class doesn't leak
into the rest of the program.

class Account {
